# Scrolling evidence and validation boundaries

## Selected behavior

The owner selected DragScroll-style immediate scrolling instead of Karabiner's accumulation/momentum behavior after observing that DragScroll felt right. This is an intentional change of compatibility target, not a claim to have completed a faithful end-to-end Karabiner port.

The source reference is [DragScroll commit 879bd0e6f4f1aae239364c5e7e49f19746729993](https://github.com/emreyolcu/drag-scroll/blob/879bd0e6f4f1aae239364c5e7e49f19746729993/DragScroll/main.c). Its callback reads Quartz mouse deltas, constructs a two-axis pixel event with `-SPEED * deltaY` and `-SPEED * deltaX`, removes activating modifier flags, inserts the event through `CGEventTapPostEvent`, and warps the cursor back to its anchor. Its default speed is 3. It does not implement software momentum or axis locking. Source-derived code is attributed in `THIRD_PARTY_NOTICES`, including the complete MIT notice.

The shared C mapping uses `-3 * speed_multiplier * delta` immediately. At multiplier `1.0`, it matches DragScroll's default integer mapping. Unlike upstream's integer-only speed preference, fractional multipliers retain fractional remainders so small motions are not permanently lost. Releasing the activation modifier resets those remainders. Both axes remain independent, with no delayed queue or timer. Nonfinite/out-of-range output fails open instead of overflowing integer event fields.

The former Karabiner counter, timer, direction lock, and momentum path are removed from the executable. Existing Karabiner recordings/importer are historical reference, not active acceptance tests. The old momentum CLI option is rejected with a migration message rather than silently pretending to affect direct scrolling.

## macOS

An active session event tap matches DragScroll's capture point. Each converted motion produces an actual Quartz pixel event within the same callback; output is inserted after the current tap rather than reposted through it. Marked own events bypass conversion. The callback reads incoming modifier flags instead of polling a hardware modifier table on a separate momentum timer. Side-specific bindings still use device-dependent flags, with a physical key-state fallback when those bits are absent. Additional held modifiers are preserved.

The cursor suppression/warping sequence follows DragScroll: a combined-session source uses a 10-second local suppression interval during activation, and movement is warped to the captured anchor. On release, the interval is set to zero before restoring the pointer, then the original interval is restored. This cleanup also runs on failure, tap disablement and normal shutdown. A separate private wheel source has local suppression disabled. Actual pinning and hardware event delivery still require a live test; source similarity and mocked warp checks do not prove them.

Clearing only wheel flags did not address Ghostty's cached keyboard modifiers: its macOS `flagsChanged` handler updates the core modifier state, and its scrolling path uses that cached state for terminal mouse reports. The backend now posts marked activating-modifier releases, one continuous pixel wheel event with both axes, and modifier restores in order within the movement callback. It builds the complete sequence before posting anything, so allocation failure cannot strand the application's keyboard state. Restores consult the physical HID key table and skip keys already released. Side-specific bindings preserve the other held side and unrelated modifiers; neither the mapping nor the event constructor imposes an axis lock. Owner live checks confirmed the Ghostty/Emacs scrolling fix and diagonal movement in Google Sheets. Other application and hardware cases remain unverified. The relevant Ghostty source is [`SurfaceView_AppKit.swift`](https://github.com/ghostty-org/ghostty/blob/main/macos/Sources/Ghostty/SurfaceView_AppKit.swift) and [`Surface.zig`](https://github.com/ghostty-org/ghostty/blob/main/src/Surface.zig).

Normal physical modifier events, mouse buttons and physical wheel input pass through. Dragged motion is converted too, preserving the prototype's existing activation scope; DragScroll's original callback handles only ordinary mouse-moved events. Mouse-button toggling, its preferences database, GUI permission prompts, and automatic startup are not imported.

Signal delivery uses system libdispatch to signal a Core Foundation shutdown source, preserving safe run-loop shutdown even if the request arrives before the loop starts. No driver, GUI framework, installation step, or third-party runtime is added. Permission probes in the current launch context now report Accessibility and Input Monitoring allowed, but this does not establish permission attribution for every rebuilt executable or other terminal.

## Windows

Raw Input supplies relative mouse deltas; a low-level hook suppresses cursor motion while the selected modifier is held. Screen-position subtraction is not used. The shared mapping runs immediately in the Raw Input handler, without a scroll timer. Physical wheel input and button-only packets are not converted or swallowed. Absolute pointing input remains unsupported and stops filtering with an error.

`SendInput` has no pixel-scroll equivalent. The backend emits three high-resolution wheel units per mouse count at speed `1.0`, without multiplying each unit into a full 120-unit notch. Horizontal sign is reversed at the Windows boundary because positive Windows horizontal wheel delta means right, unlike positive Quartz horizontal scrolling. Windows/application wheel settings and partial-notch handling determine actual distance; this is not a promise of DragScroll-identical feel.

An atomic activating-modifier up/wheel/down batch prevents Shift from turning vertical conversion into horizontal scrolling. Marked synthetic key events do not change the recorded physical activation state. Partial injection attempts modifier restoration and stops filtering; no privilege escalation or service is added. This preserves the existing prototype's Windows modifier handling rather than introducing a new input architecture.

No Windows compiler or runtime is available in this environment; the owner previously accepted deferred native validation. Compilation, Raw Input delivery while movement is suppressed, fine wheel-unit handling, cursor pinning, and modifier restoration require Windows validation. No replacement compiler, emulator or new dependency was installed.

## Regression evidence

A native callback regression was added before replacing the old macOS path. It failed because a movement callback produced no scroll event immediately. After the change, the same case produces a continuous pixel event with exact point deltas on both axes. The test uses Quartz's real event constructor, while posting and cursor mutation are intercepted so nothing reaches the user's desktop.

`make test` covers the shared direct mapping, fractional carry/reset, invalid values, CLI defaults/aliases/errors and the macOS callback. The native cases check side-specific activation, additional modifier flags, ordinary input, drag conversion, physical key fallback, release/reactivation, overflow failure and failed cursor anchoring. `make test-sanitize` runs both shared and native tests with AddressSanitizer and UndefinedBehaviorSanitizer. A second regression seeded a receiver with cached Shift and observed its keyboard modifier state at wheel delivery. Clearing wheel flags alone failed that test; the new up/wheel/down sequence passes while retaining both point deltas in one wheel event. A physical-release-during-posting case also failed before adding the HID restore guard. Native cases cover all binding families/sides, right-side fallback, ordinary typing, ordered timestamps, and allocation failure before posting. These results prove event construction and callback decisions, not on-screen displacement or live feel.

The owner subsequently tested the fixed executable and confirmed restored vertical scrolling in Ghostty/Emacs and diagonal scrolling in Google Sheets. These are live observations in those applications, not proof of every hardware, modifier or shutdown case. Keep other converters off during the remaining checklist in `README.md`.
